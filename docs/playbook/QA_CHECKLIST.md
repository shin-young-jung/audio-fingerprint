# 완료 기준 · 검수 체크리스트 (범용)

모든 작업 지시의 '완료 기준'에 이 문서를 넣는다. 프로젝트별 명령은 그 프로젝트의 `CLAUDE.md` 에 있다.

## 1. 공통 완료 기준
- 테스트 통과, 타입 검사 오류 0, 빌드 성공
- 바뀐 화면을 브라우저에서 직접 확인, 콘솔 오류 0
- 권한이 걸린 변경이면 역할마다(최고 권한·일반 편집·읽기 전용·플랫폼 운영자 등) 확인
- 보고: 바뀐 파일, 시나리오별 '조작 → 본 결과', 해 보지 않은 것은 **'미확인'으로 따로**

## 2. 화면 검수 (화면을 바꿨으면)
- 폭 **375 / 768 / 1280~1440 / 1920**, 페이지 전체 가로 스크롤 없음(넓은 표는 표 안에서만 스크롤)
- 첫 로딩 직후 상태, 로딩·빈 상태·오류 상태
- 정렬 순서(월·분기·기수는 자연 정렬), 축·범례·라벨 잘림·겹침
- 카드·칸 넘침, 이중 스크롤바(카드 안 표는 행만 스크롤되고 머리·페이지 넘김은 고정되는지)
- 숫자 형식(음수·통화·축약·소수점), 날짜 형식(시간대 때문에 하루 밀리지 않는지)
- 글자 줄바꿈: 좁은 칸에서 칩·버튼 글자가 두 줄로 꺾이지 않는지(`white-space: nowrap`, 덜 중요한 요소가 먼저 줄어들게)
- 테스트 흔적 문구(QA, test, 임시 값)가 화면에 남지 않았는지
- 계정·조직 전환 후 이전 사용자의 데이터·메뉴가 남지 않는지

## 3. 상호작용 검수
- 키보드: Tab 으로 이동, Enter/Space 로 실행, **Esc 로 팝업·모달 닫힘**(팝업이 모달 안이면 첫 Esc 는 팝업만)
- 이벤트 전파: 버튼·아이콘을 눌렀을 때 부모(카드 선택, 행 선택, 드롭다운, 접기)가 같이 반응하지 않는지. 반대로 전파를 막은 탓에 다른 버튼이 죽지 않았는지
- 편집 중 단축키 충돌: 입력창 안의 Home/End/방향키가 표·페이지 단축키로 새지 않는지
- 값이 그대로면 저장 요청이 나가지 않는지(사용량·과금·감사 기록에 영향)
- 늦게 도착한 응답이 최신 상태를 덮어쓰지 않는지(요청 순번 확인)

## 4. 확인 요령
- **수치 먼저, 그림은 나중.** DOM 측정(`scrollWidth > clientWidth`, 요소 높이, 개수)과 API 응답으로 먼저 판정하고, 스크린샷은 모양 판단에만 쓴다(토큰 절약).
- 애니메이션이 있는 차트·팝업은 잠시 기다렸다가 다시 측정·캡처한다(전환 중 화면으로 오판하지 않기).
- 여러 계정을 동시에 볼 때는 호스트명을 다르게 연다(예: `a.localhost`, `b.localhost`) — 로그인 저장소가 섞이지 않는다.
- 네트워크 요청 검증: 필요하면 페이지에서 XHR/fetch 를 감싸 요청 본문을 기록한다(무엇이 몇 번 나갔는지).
- 권한 검증은 API 를 직접 호출한다: 다른 조직 계정으로 남의 리소스, 헤더 위조, 상한 초과 값, 읽기 전용 계정.

## 5. 문서·PDF
- 웹 페이지를 원본으로 PDF 를 만들면 화면과 문서가 어긋나지 않는다(헤드리스 브라우저 인쇄 + 인쇄 전용 CSS).
- 인쇄 CSS: 표지·목차는 인쇄 전용 블록, `@page` 여백 박스로 쪽 번호(첫 쪽 제외), 제목은 다음 내용과 붙게(`break-after: avoid`), 그림+캡션만 `break-inside: avoid`, 인쇄용 이미지 최대 높이 제한, 지연 로딩 이미지는 인쇄 모드에서 즉시 로드.
- 검수: PDF 를 쪽 이미지로 바꿔(`pdftoppm -r 30 -png`) 한 장의 모음으로 이어 붙여 본다. 표지·목차·쪽 번호·빈 쪽(장 끝 제외 40% 이상 빈 쪽 없음)·쪽 끝에 남은 제목을 확인. `pdfinfo` 로 쪽 수·제목 메타데이터·용지 크기.
- 문구는 실제 동작과 대조한다. 외부용 자료에는 지어낸 수치·고객사·후기를 넣지 않고, 가격 등 변하는 값은 실제 데이터에서 읽는다.

## 6. 데이터 보호
- 검수 중 DB 데이터를 바꿨다면(테스트 편집 등) 원래 값으로 되돌리고 보고한다. 사용자가 남기라고 한 테스트 데이터는 지우지 않는다.
- 승인·삭제·발송처럼 되돌릴 수 없는 버튼은 검수 중 누르지 않는다(창만 열어 보고 취소).
