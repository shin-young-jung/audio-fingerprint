# CLAUDE.md 뼈대 (범용)

새 프로젝트 루트에 `CLAUDE.md` 를 만들 때 아래를 복사해 `< >` 를 채운다. 모든 세션(관리자·하위)이 자동으로 읽으므로 **역할 지시는 넣지 않는다**(역할은 `docs/playbook/ARCHITECTURE_PROMPT.md`·`docs/claude-ops/*_PROMPT.md` 로 준다). 비밀번호·토큰은 절대 넣지 않는다(이 파일은 저장소에 올라간다).

````markdown
# <제품명> — 모든 세션 공통 규칙

<제품이 무엇인지 한두 줄>. 사용자에게는 <언어>로, 결론부터 짧게 말한다. 맡은 역할은 각 세션이 받은 지시를 따른다.
공통 작업 기준은 `docs/playbook/QA_CHECKLIST.md`.

## 구조
| 경로 | 내용 |
|---|---|
| `<경로>` | <무엇> |

<권한 모델이 있으면 한 줄: 역할 이름과 차이>

## 명령
<런타임 버전 맞추는 법(예: nvm use 22)>

| 할 일 | 명령 |
|---|---|
| 개발 서버 | <> |
| 테스트 | <> |
| 타입 검사 | <> |
| 빌드 | <> |
| 데모/시드 데이터 | <> |
| DB 스키마 변경 | <절차 또는 문서 위치> |
| 배포 | <명령> 후 <상태 확인 주소> |

데모 계정: <계정 목록(비밀번호는 데모용만)>

## 완료 기준 (코드를 바꿨으면 매번)
1. <테스트> 통과, <타입 검사> 오류 0, <빌드> 성공

4. 보고: 바뀐 파일, 시나리오별 "조작 → 본 결과", 해 보지 않은 항목은 "미확인"으로 따로

## 지켜야 할 것
- 접속 정보는 <.env 위치> 에만 둔다. 커밋·출력·보고서에 넣지 않는다.
- <서버 접속 방법과 건드리면 안 되는 것>
- <남겨 둬야 할 데이터, 되돌릴 수 없는 작업은 먼저 묻기>
- 커밋·푸시·배포는 받은 지시가 허락할 때만 한다. 저장소: <주소> (<기본 브랜치>)
- 여러 세션이 같은 작업 폴더를 쓸 수 있다. 맡은 파일 밖은 고치지 않는다.
````
