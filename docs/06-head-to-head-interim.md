## 2. 지금까지 확인된 결과

### 2.1 기준선 — SD-RR 실제 아이폰 녹음 (전체 쿼리)

| 쿼리 길이 | 1초 | 2초 | 3초 | 5초 | 10초 |
|---|---|---|---|---|---|
| Top-1 | 18.4 | 35.0 | **47.3** | 65.0 | 81.7 |
| 정답 수락률 (점수 ≥ 8) | 2.4 | 10.3 | **20.0** | 39.7 | 65.7 |

→ 실제 휴대폰 녹음에서 **샤잠식 기준선은 3초 인식이 사실상 불가능**한 수준이다.

### 2.2 후보 B 구현 검증 (중요)

- 처음 측정에서 B가 비정상적으로 낮았다(10초 47%).
- 원인은 **제 검색 구현**이었다. 특정 곡("허브")의 구간이 후보 목록을 차지해 정답 곡이 비교조차 되지 않았다.
- 전수 채점 방식으로 수정하자 10초 47% → 59%(1,011곡 DB, 120개 표본)로 올랐다.
- **논문 재현 검증:** POLARIS 논문(Table 2)과 같은 조건(DB 496곡, 10초, 1,488개)으로 돌리고 있다. 1,200개 시점 Top-1이 **74.8%** 로, 논문의 NMFP **74.33%** 와 일치한다. 따라서 구현은 원본과 같다고 판단한다.
- 디코더 차이(ffmpeg vs essentia)의 영향은 120개 표본에서 +1.7%p로 작았다.

### 2.3 규모 민감도 (B)

- 같은 120개 쿼리(10초): DB 496곡 65.8% → 1,011곡 59.2% (**-6.6%p**)
- 추가된 FMA 곡 중 일부가 허브가 되어 오답을 끌어들였다.
- 100만 곡 목표에서 **신경망 방식의 핵심 위험**이다. 후보 A의 규모 민감도는 아직 측정하지 않았다.

### 2.4 참고: POLARIS 논문의 SD-RR 수치 (10초, DB 496곡, 논문 저자 측정)

## 4. 재현 방법

```bash
# 인덱스 (1,011곡 목록: docs/results/head2head/refs1k.txt)
python -m afp.evaluate build --method landmark|triangle --out idx.npz <refs>
python -m afp.evaluate build --method neural --ckpt <nmfp-triplet>/ckpt-100 --out idx.npz <refs>
# SD-RR 실제 녹음 평가 (쿼리별 결과는 --dump)
python -m afp.evaluate sdrr --index idx.npz --root <SD-RR-v1.0> --dump dump.csv
# 같은 오인식률에서 비교
python -m afp.compare baseline=dump_a.csv A=dump_b.csv
```
