## 2. 지금까지 확인된 결과

### 2.1 기준선 — SD-RR 실제 아이폰 녹음 (전체 쿼리)

| 쿼리 길이 | 1초 | 2초 | 3초 | 5초 | 10초 |
|---|---|---|---|---|---|
| Top-1 | 18.4 | 35.0 | **47.3** | 65.0 | 81.7 |
| 정답 수락률 (점수 ≥ 8) | 2.4 | 10.3 | **20.0** | 39.7 | 65.7 |

→ 실제 휴대폰 녹음에서 **샤잠식 기준선은 3초 인식이 사실상 불가능**한 수준이다.

### 2.2 후보 B 구현 검증 (중요)

- 처음 측정에서 B가 비정상적으로 낮았다(10초 47%).
- 원인은 **제 검색 구현**이었다. 특정 곡("허브")의 구간이 후보 목록을 차지해 정답 곡이 비교조차 되지 않았다.
- 전수 채점 방식으로 수정하자 10초 47% → 59%(1,011곡 DB, 120개 표본)로 올랐다.
- **논문 재현 검증 (완료):** POLARIS 논문(Table 2)과 같은 조건(DB 496곡, 10초, 1,488개 전체)에서 Top-1 **74.19%**, 곡+위치 71.30%가 나왔다. 논문의 NMFP는 **74.33%** / 71.17%다. 구현이 원본과 같다고 판단한다.
- 디코더 차이(ffmpeg vs essentia)의 영향은 120개 표본에서 +1.7%p로 작았다.

### 2.3 규모 민감도 (B)

- 같은 120개 쿼리(10초): DB 496곡 65.8% → 1,011곡 59.2% (**-6.6%p**)
- 추가된 FMA 곡 중 일부가 허브가 되어 오답을 끌어들였다.
- 100만 곡 목표에서 **신경망 방식의 핵심 위험**이다. 후보 A의 규모 민감도는 아직 측정하지 않았다.

### 2.5 세 방식 직접 비교 — 같은 쿼리 496개 (SD-RR 1/3, 실제 아이폰 녹음, DB 1,011곡)

`scripts/subset_compare.py`, 원본 데이터는 `docs/results/head2head/compare_sdrr_sub.csv`.

| 방식 | 길이 | Top-1 | 정답 수락률 (오인식 1%) | 정답 수락률 (오인식 0.1%) | 쿼리 시간 (CPU, 파이썬) |
|---|---|---|---|---|---|
| 기준선 (샤잠식) | 3초 | 42.3 | 15.3 | 3.8 | 8 ms |
| A (삼각형 해시) | 3초 | **50.0** | 12.5 | 0.2 | 429 ms |
| B (신경망 NMFP) | 3초 | 47.8 | **19.8** | **17.7** | 417 ms |
| 기준선 (샤잠식) | 10초 | **77.4** | 32.7 | **11.1** | 29 ms |
| A (삼각형 해시) | 10초 | 77.2 | 23.6 | 1.8 | 319 ms |
| B (신경망 NMFP) | 10초 | 60.9 | **34.7** | 7.7 | 1,146 ms |

후보 A 전체 SD-RR(쿼리 13,392개) Top-1: 1초 15.3 / 2초 40.5 / 3초 54.8 / 5초 69.0 / 10초 80.2.

**해석 (중간 판단)**

1. **이 조건(노트북 스피커 → 아이폰 음성 메모)에서는 세 방식 모두 3초 목표에 크게 못 미친다.** 음성 메모 앱의 자체 음성 처리가 들어간 가혹한 조건이다.
2. **"틀린 곡을 내지 않으면서 맞히는" 능력은 3초에서 B가 가장 좋다**(오인식 0.1%에서 17.7%). 서비스에서는 오답이 "못 찾음"보다 나쁘므로 중요한 지표다.
3. **A는 Top-1은 가장 높지만 오인식 억제가 매우 약하게 측정됐다.** 우리 구현의 한계일 가능성이 크다.
   - 확신도를 "일치 해시 개수"로만 판단한다. POLARIS는 1·2등의 점수 차를 쓴다.
   - 8 kHz로 동작해 4~5.5 kHz 대역을 쓰지 못한다(논문은 40 kHz).
   - 따라서 **A는 아직 불리하게 측정됐을 수 있다.**
4. **B는 곡 수에 민감하다**(10초: 496곡 74.2% → 1,011곡 60.9%). 100만 곡 목표에서 가장 큰 위험이다.
5. **샤잠식 기준선은 10초에서는 의외로 경쟁력이 있지만, 3초에서는 가장 약하다.**

**지금 결론:** 어느 후보도 "그대로 쓰면 된다"는 수준이 아니다. 그래서 D4(주 알고리즘)는 아래 보완 측정 후에 결정한다.
- A: 확신도 판정 개선, 16 kHz 입력
- B: 우리 녹음 환경에 맞춘 학습, 규모 대응
- 공통: 우리 앱 녹음 설정(음성 처리 끈 상태)으로 만든 테스트셋

## 4. 재현 방법

```bash
# 인덱스 (1,011곡 목록: docs/results/head2head/refs1k.txt)
python -m afp.evaluate build --method landmark|triangle --out idx.npz <refs>
python -m afp.evaluate build --method neural --ckpt <nmfp-triplet>/ckpt-100 --out idx.npz <refs>
# SD-RR 실제 녹음 평가 (쿼리별 결과는 --dump)
python -m afp.evaluate sdrr --index idx.npz --root <SD-RR-v1.0> --dump dump.csv
# 같은 오인식률에서 비교
python -m afp.compare baseline=dump_a.csv A=dump_b.csv
```
