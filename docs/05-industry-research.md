# 상용 음원 검색 서비스 기술 조사

> 작성일: 2026-11-05 · 관련: [04. 알고리즘 선택 결정 문서](04-algorithm-decision.md)
> 범위: 샤잠(애플), 사운드하운드, 구글, 네이버, 멜론·지니 등 국내 서비스, B2B 업체(ACRCloud, Gracenote)
> **주의:** 상용 서비스의 내부 구현은 대부분 비공개다. 이 문서는 공개 자료(논문, 특허, 공식 문서·블로그, 기사)만 근거로 한다. 출처마다 신뢰도를 표시했다.

| 표시 | 의미 |

| 📄 | 특허 문서(그 회사가 특허를 냈다는 사실이지, 지금 그 방식을 쓴다는 증거는 아님) |

## 0. 결론 먼저

1. **1억 곡 규모에서 두 가지 방식이 모두 검증돼 있다.**
   - 샤잠은 **스펙트럼 피크 해시**(2003년 논문 계열)로 출발했다 ✅. 그 뒤 방식을 바꿨다는 공개 자료는 없다 ❓.
   - 구글은 **신경망 임베딩**으로 휴대폰 안(수만 곡)과 서버(1억 곡 수준)에서 운영한다 ✅📰.
   - → 우리 목표인 100만 곡은 **어느 방식으로도 규모 자체는 가능한 수준**이다. 선택의 핵심은 규모가 아니라 **시끄러운 환경 성능, 인덱스 비용, 팀 역량, 특허**다.
2. **모든 서비스가 같은 구조를 쓴다.** 휴대폰에서 특징(DNA)만 뽑아 서버로 보내고, 서버의 대형 DB와 대조한다(샤잠 ✅, 네이버 📰, 구글 ✅).
   → 결정 D1(클라이언트 DNA 추출 + 서버 2단계 검색)과 일치한다.
3. **"같은 음원 찾기"와 "허밍·커버 찾기"는 별도 엔진이다.** 구글(Sound Search / Hum to Search), ACRCloud(핑거프린트 / 커버·허밍), 사운드하운드(녹음 음원 / 노래·허밍)가 모두 나눠서 운영한다.
   → 우리 프로젝트 범위는 **같은 음원 찾기**로 한정하는 것이 업계 관행과 맞다. 허밍 검색은 별도 과제로 둔다.
4. **특허는 두 방식 모두에 걸려 있을 수 있다.** 샤잠 원천 특허(2001년 출원)는 존속기간이 지났을 가능성이 높지만, 후속 특허가 많고 현재 애플 소유다 📄. 구글도 신경망·멜로디 지문 관련 특허를 보유하고 있다 📄.
   → **어느 방식을 고르든 특허 조사(FTO)가 필요하다.** 결정 문서의 게이트에 추가할 항목이다.

## 1. 샤잠 (Shazam, 2018년 애플 인수)

| 항목 | 내용 | 신뢰도 |
|---|---|---|
| 핵심 방식 | 스펙트로그램에서 피크만 남기고, 두 피크를 묶어 (주파수1, 주파수2, 시간차) 해시를 만든다. 서버에서 해시를 찾은 뒤 **시간차가 일정하게 맞는 해시 개수**로 곡을 판정한다. | ✅ Wang 2003 논문 |
| 원천 특허 | US6990453 (Wang·Smith, 2001년 4월 출원). 2020년 애플로 권리 이전 기록. Google Patents 표시 만료일 2024-01-07(조정값, 공식 확인 아님) | 📄 |
| 후속 특허 | Wang 발명, Shazam Investments/Entertainment 명의 특허가 2017~2019년에도 다수 등록 | 📄 |
| 앱 구조 | ShazamKit은 오디오를 **"Signature"** 형식으로 바꿔 매칭한다. 애플 설명: 압축되고 손실이 있는 표현이며, **원래 소리로 되돌릴 수 없다**(개인정보 보호). | ✅ 애플 개발자 문서 |
| 쿼리 길이 | 시그니처 길이 약 3~12초(개발자 경험담) | 📰 |
| 규모 | 2024년 11월 누적 인식 1,000억 회 ✅. 2025년 월 10억 회 이상(애플 발표 인용) 📰. 카탈로그는 2014년 기준 1,100만 곡 이상(오래된 강의 자료) 📰 | ✅📰 |
| 최근 기능 | iOS 26.4 오프라인 인식: 녹음을 저장해 뒀다가 연결되면 서버에서 인식하는 방식으로 보도됨. **휴대폰 안 매칭은 확인 안 됨.** | 📰 |
| 신경망 전환 여부 | 공개 자료 없음 | ❓ |
| 역공학 | 오픈소스 `vibra`가 샤잠 시그니처 형식을 재현했다고 주장(제3자 주장, 미확인) | 📰 |

**우리에게 주는 의미**
- 피크 해시 계열이 수천만 곡·하루 수천만 회 규모에서 20년 넘게 운영됐다. 방식 자체의 확장성은 검증돼 있다.
- 다만 우리 측정에서 단순 피크 쌍 방식은 인덱스 크기와 정확도의 맞교환이 불리했다(04 문서 2.3절). 샤잠이 이를 어떻게 해결했는지는 비공개다. 공개된 후속 특허 분석이 다음 조사 대상이다.

## 2. 사운드하운드 (SoundHound, 구 Midomi)

| 항목 | 내용 | 신뢰도 |
|---|---|---|
| 브랜드 기술 | **Sound2Sound(S2S)**. 녹음 음원은 "유연한 핑거프린트"로 녹음 음원 DB와 대조한다. 노래·허밍은 **멜로디와 리듬**을 사용자 녹음 수백만 개와 대조하며, **음높이와 템포가 달라도 매칭**된다. 말로 하는 검색은 곡명·가수명의 발음 표현과 대조한다. | ✅ Midomi 공식 도움말 |
| 특허 | US8452586 "Identifying music from peaks of a reference sound fingerprint"(우선일 2008-12-02). 청구항에 쿼리의 **특징 행렬**을 기준 곡 행렬과 비교하고, **필터뱅크 피크의 일치·불일치**를 프레임별 점수로 합산하는 방법이 있다. | 📄 |
| 그 밖의 특허 | "Systems and methods for sound recognition"(8688253), "System and method for identifying original music"(2013 공개) | 📄 |
| 허밍 데이터 | 초기 Midomi는 **사용자가 부른 노래를 수집**해 허밍 DB로 활용한 것으로 알려짐 | 📰 |
| 현재 | 회사의 중심은 음성 AI 플랫폼(Houndify)으로 이동. 음악 인식 엔진의 최근 변화는 공개 자료 없음 | ❓ |

**우리에게 주는 의미**
- 사운드하운드 특허는 샤잠식 "피크 쌍 해시"가 아니라 **프레임 단위 피크 패턴 비교** 계열이다. 피크 기반이어도 해시 설계는 여러 가지라는 사례다.
- 허밍 검색은 별도 기술(멜로디·리듬, 음높이·템포 불변)이고, 데이터 수집 전략이 핵심이었다.

## 3. 구글 (Now Playing / Sound Search / Hum to Search)

| 서비스 | 방식 | 규모 | 신뢰도 |
|---|---|---|---|
| **Now Playing** (2017, 픽셀폰) | 신경망 임베딩. 저전력 DSP의 음악 감지기가 음악일 때만 메인 CPU를 깨우고, **휴대폰 안 DB**에서 최근접 이웃 검색 + 연속 일치로 확정. 배터리 하루 1% 미만 | 수만 곡(기기 내) | ✅ 논문 |
| **Sound Search** (2018, 서버) | Now Playing 기술을 서버로 확장. 신경망 약 4배, 임베딩 1초→0.5초 간격, 96→128차원(언론 보도). 공간분할 + 벡터 양자화로 검색. **인기곡일수록 판정 기준을 낮춤** | 수천만 곡 ✅ / 2020년 약 1억 곡 📰 | ✅📰 |
| **Hum to Search** (2020) | 허밍을 **멜로디 임베딩**으로 바꿔 원곡 스펙트로그램의 임베딩과 비교. 중간 단계(음표 추출) 없이 바로 임베딩. triplet 손실로 학습. 음높이·템포 변형 증강. 반주·목소리 음색은 무시하도록 학습 | 출시 때 50만 곡 이상 📰 | ✅ 공식 블로그 |

**우리에게 주는 의미**
- **신경망 방식이 1억 곡 규모 상용 서비스에서 운영된다는 공식 근거다.** 신경망을 "검증 안 된 연구 기술"로 볼 이유는 없다.
- 인기도 기반 판정 기준, 0.5초 간격, 벡터 양자화는 바로 참고할 수 있는 설계다.
- 구글은 학습 데이터·GPU·ML 인력이 충분한 회사다. 우리가 같은 방식을 택하면 **이 역량이 필요하다**는 점도 함께 봐야 한다.

## 4. 네이버

| 항목 | 내용 | 신뢰도 |
|---|---|---|
| 출시 | 2010년 10월, **자체 기술**로 만든 음악검색 앱을 국내 최초로 출시 | 📰 테크월드뉴스 |
| 동작 | 앱이 몇 초 녹음 → **특징 정보만 추출해 서버 전송** → 서버가 음원 DB와 대조. 특징 추출은 "주파수 대역별로 나눠 잡음·변형에도 구별되는 정보"를 찾는 방식으로 설명됨. 결과까지 최대 약 10초 | 📰 (2019년 무렵 기사) |
| 현재 위치 | 네이버 앱 그린닷 AI 검색의 "음악검색" 기능. 마이크 → "노래 검색"으로 **허밍 검색**도 제공(개인 블로그) | ✅ 앱스토어 / 📰 |
| 상세 알고리즘 | 공식 기술 발표(DEVIEW 등)·논문·특허를 찾지 못함 | ❓ |
| 국내 특허 경향 | 국내 특허 다수가 **필립스식 32비트 서브 핑거프린트**(33개 대역, 256개 = 1블록, 룩업 테이블 검색) 구조를 쓴다(예: KR102101410B1, KR101286862B1). **출원인이 네이버인지는 확인 못 함** | 📄 |

**추정(확인 안 됨):** 2010년 국내 기술 환경과 기사 설명("주파수 대역별 특징")을 보면, 초기 엔진은 필립스식 비트열이나 피크 기반 고전 방식이었을 가능성이 있다. 그 뒤 신경망으로 바뀌었는지는 알 수 없다 ❓.

## 5. 멜론·지니 등 국내 음원 서비스

| 서비스 | 확인된 것 | 신뢰도 |
|---|---|---|
| 멜론 (카카오엔터테인먼트) | 앱에 음악검색 기능. **멜론에 등록된 음원만** 검색되고 허밍·미발매 음원은 안 된다는 설명. 나무위키는 **"네이버 앱 음원검색과 같은 기능"** 이라고 기술 | 📰 (위키, 확인 필요) |
| 멜론 스마트 i (2017) | 카카오 **음성인식** + 멜론 음악 데이터를 결합한 음성 검색. 음원 인식 엔진과는 다른 기능 | ✅ 카카오 보도자료 |
| 지니 (KT 계열) | 음악 인식 엔진 출처를 확인하지 못함 | ❓ |
| 엔써즈 | 오디오 핑거프린팅을 영상 검색에 적용한 국내 업체. 2011년 KT가 지분 45% 인수 → 2015년 **그레이스노트에 매각** → 이후 닐슨 소속. 지니와의 연결은 확인 못 함 | 📰 |
| 뮤레카 (음악인식 업체, 2004년 무렵) | 방송음악 실시간 모니터링 '에어모니터'. 현재 활동은 확인 못 함. 같은 이름의 AI 작곡 서비스(중국 Kunlun)와는 다른 회사 | 📰 |

**우리에게 주는 의미**
- 국내 음원 서비스는 자체 엔진보다 **외부 엔진이나 포털 기술을 쓰는 경우가 있는 것으로 보인다**(확인 필요). 우리 엔진을 B2B로 공급할 시장이 있을 수 있다.
- 국내 음원 메타데이터·권리 정보를 가진 사업자와의 제휴가 DB 구축(100만 곡 확보)의 현실적 경로일 수 있다.

## 6. B2B 인식 업체

| 업체 | 공개된 내용 | 신뢰도 |
|---|---|---|
| **ACRCloud** | 핑거프린트 DB **1억 5천만 곡 이상**(자체 발표). 엔진 분리: 오디오 핑거프린트(**같은 버전만** 찾음) / 커버·허밍 인식(라이브·커버·허밍, 허밍 DB 100만 곡 이상) / 파생물 탐지(속도·음높이 변형, 리믹스). 결과에 신뢰도 점수. 고객이 자기 서버에서 핑거프린트를 만들어 올리는 도구 제공 | ✅ 공식 문서 (자체 발표 수치) |
| **Gracenote** (닐슨) | MusicID: 자체 오디오 핑거프린트, 편집팀이 관리하는 대형 DB. 자동차·가전, 방송 모니터링, 권리 정산에 사용. 알고리즘은 비공개 | ✅ 마케팅 자료 |

**우리에게 주는 의미**
- **ACRCloud는 직접 비교 대상(경쟁사이자 기준점)** 으로 쓸 수 있다. 같은 휴대폰 녹음 테스트셋을 ACRCloud API와 실제 샤잠 앱에 넣으면 상용 수준과의 차이를 숫자로 확인할 수 있다. → 04 문서 G1에 추가 권장.
- "빠르기·음높이 변형 탐지"가 별도 상품이라는 점은, 기본 핑거프린트가 이런 변형에 약하다는 업계 인식을 보여준다.

## 7. 알고리즘 결정에 반영할 점

| # | 반영 사항 | 근거 |
|---|---|---|
| R1 | "피크 해시 vs 신경망"은 **둘 다 상용 1억 곡 규모에서 검증된 방식**이다. 결정 기준은 규모가 아니라 실녹음 성능, 비용, 역량, 특허다. | 샤잠 ✅, 구글 ✅ |
| R2 | 클라이언트 DNA 추출 + 서버 대조 구조(D1)는 업계 표준이다. DNA는 **원음 복원이 불가능**해야 한다(개인정보). | 샤잠 ✅, 네이버 📰 |
| R3 | 범위는 **같은 음원 식별**로 한정한다. 허밍·커버는 별도 엔진·별도 과제로 둔다. | 구글, ACRCloud, 사운드하운드 |
| R4 | G1 맞대결에 **실제 샤잠 앱과 ACRCloud**를 기준점으로 넣는다. | 상용 수준 비교 |
| R5 | **특허 조사(FTO)** 를 결정 게이트에 추가한다. 대상은 애플(샤잠) 후속 특허, 구글 신경망·멜로디 지문 특허, 사운드하운드 피크 특허, 국내 서브 핑거프린트 특허. | 📄 |
| R6 | 인기도 기반 판정 기준을 서버 설계에 넣는다. | 구글 ✅ |
