# 휴대폰 재녹음 테스트셋 구축 절차서

> 목적: 논문 벤치마크(합성 왜곡)는 실제 성능을 부풀린다([02 문서](02-deep-review.md) 참고). 그래서 **우리 서비스 환경과 같은 실제 녹음**으로 모든 방식을 비교한다.
> 이 테스트셋이 모든 기술 결정의 기준이 된다.

---

## 1. 구성 목표 (1차)

| 항목 | 목표 | 비고 |
|---|---|---|
| 참조 곡 | 200곡 이상 | 장르 분산: 발라드, 댄스/EDM, 힙합, 록, 트로트, 클래식, 어쿠스틱. 조용한 곡과 가사 위주 곡 포함 |
| 녹음 쿼리 | 곡당 30초 × 조건 6개 이상 | 30초 녹음 1개에서 1/2/3/5초 쿼리를 잘라 씀 |
| **DB에 없는 곡** | 50곡 이상 | **오인식률 측정용.** 같은 장르, 비슷한 분위기로 고르고 커버곡·리믹스도 포함 |
| 기종 | 5종 이상 | 아이폰 2종, 갤럭시 2종, 저가 안드로이드 1종 |

## 2. 녹음 조건 (환경 × 거리)

| 코드 | 환경 | 재생 장치 | 거리 | 배경 소음 |
|---|---|---|---|---|
| `Q1` | 조용한 방 | 블루투스 스피커 | 1 m | 없음 |
| `Q3` | 조용한 방 | 블루투스 스피커 | 3 m | 없음 |
| `C2` | 카페 | 매장 스피커 또는 휴대 스피커 | 2~5 m | 대화, 그릇 소리 |
| `V1` | 자동차 | 차량 오디오 | 운전석 | 주행 소음, 창문 닫음 |
| `S5` | 매장/식당 | 천장 스피커 | 5 m 이상 | 대화, 매장 소음 |
| `O3` | 야외 | 휴대 스피커 | 3 m | 바람, 차량 |
| `TV` | 거실 | TV 스피커 | 3 m | 생활 소음 |

- 재생 음량은 "일상적으로 듣는 크기"로 맞춘다. 환경마다 소음 측정 앱으로 dB 값을 기록한다.
- 같은 곡이라도 **곡 안의 시작 위치를 다르게**(도입부, 1절, 후렴, 간주) 녹음한다.

## 3. 녹음 앱 설정 (매우 중요)

기본 녹음 앱은 노이즈 억제, 자동 음량(AGC), 에코 제거가 켜져 있어서 실제 서비스 앱과 결과가 달라진다. **서비스 앱에서 쓸 설정과 같게** 녹음한다.

| OS | 설정 |
|---|---|
| Android | `AudioSource.UNPROCESSED`(지원 기기) 또는 `VOICE_RECOGNITION`, 44.1/48 kHz, 16비트, 모노 |
| iOS | `AVAudioSession` 카테고리 `.record`, 모드 `.measurement`, 48 kHz, 모노 |

- 파일 형식: **WAV(무압축)**. 압축 영향은 평가 단계에서 따로 시뮬레이션한다.
- 1차에서는 간단히 기기별 "음성 메모" 앱으로 시작해도 된다. 대신 메타데이터에 앱 이름을 꼭 기록한다.

## 4. 파일 이름과 메타데이터

```
recordings/{device}_{condition}_{track_id}_{take}.wav
예) galaxyS24_C2_T0123_1.wav
```

`recordings/meta.csv`:

| 열 | 예 | 설명 |
|---|---|---|
| file | galaxyS24_C2_T0123_1.wav | |
| track_id | T0123 | DB에 없는 곡이면 `NEG_0012` |
| in_db | 1 | 0 = DB에 없는 곡 |
| start_sec | 62.0 | 원곡의 몇 초부터 재생했는지(대략, ±2초) |
| device | galaxyS24 | |
| app | unprocessed-recorder | |
| condition | C2 | |
| distance_m | 3 | |
| noise_db | 68 | 소음 측정 앱 값 |
| notes | 에어컨 소음 | |

- `start_sec`가 대략적이어도 괜찮다. 평가 도구가 상호상관으로 정확한 위치를 보정한다(`afp/evaluate.py`의 `song_spans`와 같은 방식).

## 5. 저작권·보관

- 테스트용 녹음과 원곡은 **저장소에 커밋하지 않는다.** 별도 내부 저장소(NAS나 클라우드 버킷)에 보관한다.
- 상용 음원을 쓸 때는 내부 평가 목적임을 명시하고, 사용 범위를 법무와 확인한다.

## 6. 평가 실행

```bash
# 1) 참조 곡 인덱스 생성
python -m afp.evaluate build --out runs/idx.npz refs/*.wav

# 2) 실제 녹음 평가 (현재 도구는 '연속 재생 녹음' 형식 지원,
#    개별 파일 + meta.csv 형식은 다음 작업에서 추가)
python -m afp.evaluate recording --index runs/idx.npz --recordings rec.wav \
    --order order.csv --songs-dir refs --lengths 1 2 3 5

# 3) 대규모 DB 시뮬레이션 (가짜 곡 N개 추가)
python -m afp.evaluate recording ... --distractors 5000
```

## 7. 합격 기준 (초안, 측정 후 조정)

| 지표 | 3초 쿼리 목표 |
|---|---|
| 정답 수락률 (조용한 방 Q1/Q3) | ≥ 95% |
| 정답 수락률 (카페·차량 C2/V1) | ≥ 85% |
| 정답 수락률 (매장 S5, 야외 O3) | ≥ 70% |
| **오인식률 (DB에 없는 곡을 다른 곡으로 판정)** | ≤ 0.5% |
| 서버 검색 지연 p99 | ≤ 300 ms |
