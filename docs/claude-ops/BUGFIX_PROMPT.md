# 버그 수정·작은 개선 세션 프롬프트 (범용)

**언제:** 구축이 끝난 뒤의 버그 수정·작은 개선. 버그를 몇 개 모아 한 번에. 큰 기능 묶음은 [MANAGER_PROMPT.md](MANAGER_PROMPT.md).
운용 원칙 전체는 [README.md](README.md).
**준비:** 새 대화에서 모델 **Sonnet · 보통**. 아래 `---` 사이를 붙여 넣고 **버그 목록**을 채운다(스크린샷이 있으면 함께). 묶음이 끝나면 세션을 보관하고 다음 묶음은 새 세션으로.
원인을 못 찾거나 설계를 바꿔야 하면 세션이 멈추고 알려 준다 → 모델을 Opus 로 바꾸고 "이어서 진행".

---

아래 버그 목록을 이 세션에서 끝까지 처리해라: 재현 → 원인 → 수정 → 확인 → 커밋·푸시 → 배포 → 보고.
프로젝트 규칙(명령, 완료 기준, 배포, 보안)은 `CLAUDE.md`, 공통 기준은 `docs/playbook/QA_CHECKLIST.md` 를 따른다.

## 진행 방법
1. **재현 먼저.** 버그마다 로컬에서 재현한다(계정·순서·화면 폭). 재현이 안 되면 고치지 말고 시도한 방법을 보고한다.
2. **원인을 짚는다.** `파일:줄` 까지. 같은 원인으로 생기는 다른 증상도 찾는다. 증상만 가리는 수정은 하지 않는다.
3. **최소 수정.** 관계없는 리팩터링·정리는 하지 않는다.
4. **빠뜨리기 쉬운 경우:** 로그아웃·만료, 계정·권한·조직 전환, 탭 두 개, 빈 데이터, 새로고침 없이 이동, 모바일 폭, 키보드(Enter/Esc/Tab), 모달·카드 같은 컨테이너 안.
5. **확인.** 원래 재현 순서로 다시 해서 사라졌는지 본다. 고친 곳 주변 기능도 한 번 본다. 화면을 바꿨으면 QA_CHECKLIST 의 화면 검수까지.
6. **멈출 때:** 원인을 30분 안에 못 찾거나, DB 구조·권한 정책·API 계약을 바꿔야 하면 그 버그는 멈추고 단서를 보고한 뒤 나머지를 계속한다.
7. **마무리.** 확인이 모두 통과하면 버그 묶음을 커밋 하나로(메시지에 고친 버그 나열), 푸시, 배포. 배포된 주소에서 상태 확인과 고친 화면 하나 이상을 직접 본다.

## 보고 형식 (짧게)
- 첫 줄: 몇 건 고쳤고 몇 건 남았는지, 배포했는지
- 버그마다: 원인(`파일:줄`) / 고친 내용 / 확인한 조작 → 본 결과
- 해 보지 않은 확인은 **'미확인'으로 따로**, 멈춘 버그는 이유와 단서
- 커밋 해시
